# Contributing Guidelines

Thank you for considering contributing to the **VMware Virtualization Optimization Toolkit**!  
We welcome improvements, bug fixes, and new ideas that enhance the project.

---

## 🛠️ How to Contribute

1. **Fork the repository**  
   Create your own copy of the repo to work on.

2. **Create a new branch**  
   Use descriptive names for branches, e.g.:
git checkout -b feature/add-vmotion-logging

3. **Make your changes**  
- Follow PowerShell best practices.
- Keep scripts modular and well-documented.
- Add comments explaining logic and parameters.

4. **Test your changes**  
Ensure scripts run correctly in VMware vSphere environments.  
Provide sample outputs or screenshots if possible.

5. **Commit with clear messages**  
Example:
git commit -m "Add logging to Balance-Workloads.ps1 for audit tracking"

6. **Push and create a Pull Request (PR)**  
Submit your PR with a clear description of:
- What was changed
- Why it improves the project
- Any testing performed

---

## 📖 Code Style

- Use **PowerShell naming conventions** (`PascalCase` for functions, `camelCase` for variables).
- Include **parameter validation** where applicable.
- Add **inline comments** for complex logic.
- Scripts should be **idempotent** (safe to run multiple times).

---

## ✅ Good Practices

- Document new scripts in `/docs` with usage examples.
- Update `README.md` if adding new features.
- Add diagrams in `/diagrams` if architecture changes.
- Respect the **GNU GPL v3 license** when reusing or adapting code.

---

## 🤝 Community Values

- Be respectful and collaborative.
- Provide constructive feedback in PR reviews.
- Focus on clarity, maintainability, and educational value.
